# ADR 0010: Observability with Prometheus rules, exporters and generated dashboards

Status: accepted (Phase 6)

## Decisions

1. **Alerts are Prometheus rules, unit-tested with promtool.** Every alert has a
   `severity` (critical = decisions failing or at risk now, warning = degraded) and a
   `runbook_url` pointing to a section of `docs/incident_runbooks.md`. Tests fail if an
   alert lacks a promtool case or a runbook section. Alertmanager is not run locally;
   routing belongs to a deployment.
2. **Official exporters for Redis and PostgreSQL** instead of custom collectors in the app.
   The app already reports what it sees (dependency errors, fallbacks); exporters report
   the server side (up, memory vs maxmemory, connections vs max_connections). The
   PostgreSQL exporter uses a dedicated `pg_monitor` role with no table access.
3. **Exporter connection timeouts below the scrape timeout**, so a hung dependency is
   reported as `*_up = 0` rather than as a missing scrape.
4. **Freshness is exported by the API itself** (`riskstream_online_store_usable`,
   `riskstream_online_store_state{reason}`), computed with the same function the scoring
   path uses. Alternative rejected: re-deriving freshness in PromQL from heartbeats and lag,
   which would drift from the code's rules.
5. **Dashboards are generated by `scripts/build_dashboards.py`.** Consistent layout, units and
   data source; reviewable diffs; a test checks the committed JSON matches the generator, and
   `scripts/check_dashboards.py` runs every query live. Alternative rejected: hand-edited JSON
   exported from the Grafana UI (large noisy diffs, no checks).
6. **Infrastructure and model behaviour on separate dashboards**; drift and labelled
   performance wait for Phase 7.
7. **JSON logs carry `service`, `instance`, `environment`** (from `SERVICE_NAME`,
   `INSTANCE_ID`, `ENVIRONMENT`) so logs from all containers can be filtered the same way
   as metrics.

## Consequences

* Two more containers (about 11 MB each).
* A new database role and password (`RISKSTREAM_MONITOR_PASSWORD`). Existing volumes need the
  role created once by hand (see docs/local_environment.md); new volumes get it from the init script.
